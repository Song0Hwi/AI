# 1. 자동화할 반복 업무 정의

## 1.1 As-Is (수작업 프로세스)

화장품 카테고리 시장 동향 파악을 위해 담당자는 **키워드 1개당** 다음을 반복한다.

| 순서 | 수작업 내용 | 소요 시간 |
|---|---|---|
| 1 | amazon.com 접속 → 키워드 검색 → 정렬을 Best Sellers로 변경 | 1분 |
| 2 | 검색 결과 1~2페이지에서 광고(Sponsored) 항목을 육안으로 제외 | 3분 |
| 3 | 상위 상품의 순위·상품명·가격·평점·리뷰수를 엑셀에 수기 입력 | 8분 |
| 4 | 각 상품 상세 페이지 진입 → 설명·주요 특징·성분·용량 전사 | 상품당 4분 |
| 5 | 평점·리뷰수 기준으로 "벤치마크 대상 / 단순 참고" 수동 분류 | 5분 |
| 6 | 시트 정리 및 날짜별 파일 저장 | 3분 |

- **키워드 1개당 약 40분** (상품 5개 기준)
- 주 5개 키워드 모니터링 시 **주당 약 3시간 20분**

## 1.2 문제점

1. **단순 전사 노동이 대부분** — 판단이 필요한 작업은 5단계(분류) 하나뿐이고 나머지 90%는 복사·붙여넣기다.
2. **입력 오류** — 평점(4.5)과 리뷰 수(4,512)를 혼동하거나 행이 밀리는 실수가 잦다.
3. **기록의 비일관성** — 담당자마다 컬럼 구성이 달라 시계열 비교가 불가능하다.
4. **광고 혼입** — Sponsored 영역을 실제 순위로 착각해 데이터가 왜곡된다.
5. **검색 실패를 늦게 인지** — 오타나 결과 없는 키워드를 한참 뒤에야 발견한다.

## 1.3 To-Be (자동화 목표)

> **키워드 한 단어만 제출하면, 광고를 제외한 상위 N개 상품의 상세 데이터가 품질 등급별로 자동 분류·적재되고, 벤치마크급 상품은 즉시 메일로 통보된다.**

| 구분 | As-Is | To-Be |
|---|---|---|
| 담당자 개입 | 40분 전 과정 | 키워드 입력 5초 |
| 광고 제외 | 육안 판별 | 프롬프트 규칙으로 일괄 제외 |
| 품질 분류 | 사람이 판단 | 조건 분기로 자동 분류 |
| 산출물 | 담당자마다 다른 엑셀 | `벤치마킹` / `참고_일반` / `키워드_날짜` 3중 적재 |
| 실패 인지 | 나중에 발견 | 0건이면 즉시 관리자 메일 |

# 2. 자동화 도구 선정 및 선정 이유

## 2.1 선정 도구: **relay.app**

## 2.2 후보 도구 비교

| 비교 항목 | **relay.app (선정)** | Make | Zapier |
|---|---|---|---|
| 웹 페이지 본문 가져오기 | 내장 액션 (URL만 입력) | HTTP 모듈 + HTML 파싱 별도 구성 | Webhooks/Code 조합 필요 |
| AI 액션 | 내장, **출력 스키마를 필드·타입 단위로 정의** | OpenAI 모듈, 출력은 텍스트 파싱 필요 | OpenAI 앱, 구조화 출력 제한적 |
| 리스트 반복(Loop) | `For each` 기본 제공 (1,000건/run) | Iterator + Aggregator 조합 | Looping by Zapier(별도 앱) |
| 조건 분기 | `Paths` — 캔버스에 경로가 시각적으로 표시 | Router + Filter | Paths (유료 플랜) |
| 데이터 타입 변환 | `Parse as number`, `Stringify`, `Join` 내장 | 함수식 직접 작성 | Formatter 앱 별도 스텝 |
| 무료 플랜 | 월 실행 횟수 + AI 크레딧 제공 | 1,000 ops/월 | 100 tasks/월, 다단계·분기 제한 |

## 2.3 선정 사유

**① 웹 크롤링과 AI 추출이 한 도구 안에서 끝난다**
이 업무의 핵심은 "HTML 덩어리 → 구조화된 표"다. Make/Zapier는 HTTP 응답을 정규식이나 별도 파서로 가공해야 하지만, relay.app은 `Website URL` 액션이 본문 텍스트를 반환하고 AI 액션이 이를 곧바로 필드 단위로 출력한다. 아마존은 클래스명이 수시로 바뀌므로 **CSS 셀렉터 파싱보다 텍스트 → LLM 추출 방식이 유지보수 비용이 낮다.**

**② AI 출력 스키마를 UI에서 타입까지 정의할 수 있다**
Step 5·10의 `Output`에서 `순위(#숫자)`, `주요 특징(List)`, `이미지 URL 목록(List)`을 지정하면 후속 스텝에 그대로 연결된다. 텍스트 응답을 JSON 파싱하는 중간 단계가 사라져 실패 지점이 줄어든다.

**③ Loop 안에 조건 분기를 중첩할 수 있다**
본 워크플로우는 `Loop(상품 N개) → 각 상품마다 품질 조건 분기`라는 2단 구조다. Zapier 무료 플랜은 Paths를 지원하지 않고 Make는 Iterator 내부 Router 구성이 번거롭다. relay.app은 Loop 안에 Path를 그대로 넣을 수 있어 **상품별 자동 분류**가 자연스럽게 구현된다.

**④ 무료 플랜만으로 완주 가능**
유료 결제 없이 Trigger·Web·AI·Sheets·Email·Path를 전부 사용했다.

# 3. 워크플로우 설계

## 3.1 전체 구조

![워크플로우 전체 구조](images/00_workflow.png)

```
[Trigger] 1. 키워드 입력 (Form submission)
        ↓
[Action]  2. 검색 URL 생성  (encode → prepend → append 정렬 파라미터)
        ↓
    ┌───┴───┐
    ▼       ▼
 3. 1페이지  4. 2페이지        ← 검색 결과 수집
    └───┬───┘
        ▼
[AI] 5. 상위 n개 베스트셀러 추출 (광고 제외 · 중복 제거)
        ↓
╔══════ [조건 분기 ①] Step 6 ═══════════════════════════╗
║  A: 목록 is empty          │  B: 정상 진행             ║
╚═══════┬────────────────────┴───────────┬══════════════╝
        ▼                                ▼
  7. 0건 관리자 알림          ╔═[Loop] 8. 상품별 반복 ═══════════╗
     → 종료                   ║  9.  상세 페이지 가져오기        ║
                              ║  10. [AI] 상세 정보 추출         ║
                              ║  11. 평점/리뷰수 숫자 변환       ║
                              ║  ╔═ [조건 분기 ②] Step 12 ═════╗ ║
                              ║  ║ A: 평점≥4.3 AND 리뷰≥1000  ║ ║
                              ║  ║   → 13. 벤치마킹 탭 행 추가 ║ ║
                              ║  ║   → 14. 벤치마크 후보 알림  ║ ║
                              ║  ║ B: 그 외                    ║ ║
                              ║  ║   → 15. 참고_일반 탭 행 추가║ ║
                              ║  ╚═════════════════════════════╝ ║
                              ╚════════════════┬═════════════════╝
                                               ▼
                              16. Google 시트에 새 탭으로 저장
                                  (키워드 + 날짜 스냅샷)
```

## 3.2 단계별 구현

### Trigger · Step 1 — 키워드 입력

Form submission 트리거. 폼 필드 `키워드` 하나만 받으며, 이 값이 Step 2(URL 조립)·5(프롬프트)·7·14(메일 제목)·16(탭명)까지 전달된다. Responder link는 보안상 마스킹 처리했다.



### Step 2 — 검색 URL 생성

`키워드`에 세 가지 연산을 순차 적용한다.

1. `URL encode` — 공백·특수문자 처리
2. `Prepend text` — `https://www.amazon.com/s?k=`
3. `Append text` — `&s=exact-aware-popularity-rank`

세 번째 정렬 파라미터가 핵심이다. 이것이 없으면 관련도(relevance) 순 결과를 "베스트셀러"라고 부르게 되어 데이터 정의와 이름이 어긋난다.



### Step 3·4 — 검색 결과 1·2페이지 가져오기

Step 3은 `{2.검색URL}`을, Step 4는 뒤에 `&page=2`를 붙여 조회한다. 두 스텝 모두 실패 시 `Continue without a result`로 설정해 한쪽 페이지가 막혀도 워크플로우가 중단되지 않는다.


### Step 5 — 상위 n개 베스트셀러 추출 (AI)

두 페이지의 텍스트를 GPT 5.6 Sol에 넘겨 구조화 목록으로 변환한다. 출력은 `베스트셀러 목록(List)`이며 하위에 순위·상품명·가격·평점·리뷰수·상품URL 6개 필드를 갖는다.

프롬프트 제약:
- 검색 결과에 나타난 **순서 그대로** 추출
- **광고(Sponsored) 항목 제외**
- **중복 상품은 1회만** (페이지 경계 중복 방지)
- 결과가 부족하면 **있는 만큼만** (개수를 채우려는 환각 차단)


### Step 6 — 조건 분기 ① : 검색 결과 유무

**Path A — 검색 결과 없음 (0건) → 관리자 메일**
`베스트셀러 목록`이 `Is empty`일 때 진입한다.


**Path B — 정상 진행**
`No other path is matching` 으로 설정해 어떤 데이터도 누락되지 않게 했다.



### Step 7 — 검색 결과 0건 관리자 알림 (Path A)

제목에 키워드를, 본문에 키워드와 실제 호출한 검색 URL을 담아 발송한다. URL을 함께 보내는 이유는 관리자가 그 링크를 눌러 아마존에서 직접 결과 유무를 확인할 수 있어야 원인 파악이 빠르기 때문이다.


### Step 8 — Loop : 상품별 상세 정보 크롤링 (Path B)

`{5.베스트셀러 목록}`을 대상으로 `Every item in the list` 반복한다.



### Step 9 — 상품 상세 페이지 가져오기

Loop가 넘겨주는 `상품 URL`로 상세 페이지를 조회한다. 개별 상품 페이지가 실패해도 나머지 상품 처리는 계속된다.



### Step 10 — 상품 상세 정보 추출 (AI)

GPT 5.6 Terra가 Loop의 JSON 데이터와 상세 페이지 텍스트를 함께 받아 11개 필드를 출력한다.

프롬프트 제약:
- `순위·상품명·가격·평점·리뷰수·상품URL` 6개 필드는 **원본 JSON 값을 그대로 복사** → AI가 상세 페이지를 보고 값을 바꿔 쓰는 사고를 차단
- 나머지 필드만 상세 페이지 기반으로 추출
- **성분·용량은 없으면 빈 값** → 추측 금지 (화장품 데이터에서 성분 환각은 치명적)


### Step 11 — 평점/리뷰수 숫자 변환

AI가 추출한 평점은 `"4.5"`, 리뷰 수는 `"4,512"` 형태의 **문자열**이다. 이 상태로 `≥ 4.3` 비교를 걸면 사전순 비교가 되어 오판이 발생하므로, 분기 직전에 숫자로 변환한다.

| 출력 | 원본 | 연산 |
|---|---|---|
| `평점_숫자` | 10.평점 | Parse as number (en-US) |
| `리뷰수_숫자` | 10.리뷰 수 | Parse as number (en-US) |
| `이미지목록_문자열` | 10.이미지 URL 목록 | Stringify → Join(`,`) |

이미지 URL 목록은 List 타입이라 시트 셀에 그대로 들어가지 않으므로 쉼표로 이어붙였다.


### Step 12 — 조건 분기 ② : 품질 등급

**Path A — 벤치마크 후보**
`평점_숫자 ≥ 4.3` **AND** `리뷰수_숫자 ≥ 1000` (MATCHING ALL).
두 조건을 AND로 묶은 이유는, 평점만 높고 리뷰가 30개인 신상품은 통계적 신뢰도가 낮아 벤치마크 대상이 될 수 없기 때문이다.



**Path B — 참고_일반**
조건 미충족 상품이 흘러가는 기본 경로다.



### Step 13 — 벤치마킹 탭에 행 추가 (분기② Path A)

`벤치마킹` 시트 하단에 11개 필드를 매핑해 누적한다. 이미지 URL 컬럼만 Step 11의 `이미지목록_문자열`을 사용한다.



### Step 14 — 벤치마크 후보 알림 (분기② Path A)

조건을 충족한 상품이 나오면 즉시 메일로 통보한다. 제목에 키워드와 상품명, 본문에 순위·가격·평점·리뷰수·URL을 담는다.


### Step 15 — 참고_일반 탭에 행 추가 (분기② Path B)

동일한 11개 필드 구조로 `참고_일반` 시트에 누적한다. 두 탭의 스키마를 같게 유지해 나중에 통합 분석이 가능하다.



### Step 16 — Google 시트에 새 탭으로 저장

Loop 종료 후, 해당 실행의 전체 결과를 `{키워드} {yyyy-MM-dd HH:mm}` 이름의 새 탭에 스냅샷으로 남긴다.



## 3.3 3중 적재 구조의 의도

| 저장 위치 | 내용 | 성격 | 용도 |
|---|---|---|---|
| `벤치마킹` 탭 | 조건 충족 상품만 | 누적(append) | 경쟁 제품 추적 |
| `참고_일반` 탭 | 조건 미충족 상품만 | 누적(append) | 카테고리 전반 흐름 파악 |
| `{키워드} {날짜}` 탭 | 해당 실행의 전체 | 회차별 스냅샷 | 원본 보존 · 시점별 재현 |

분기별 탭은 누적, 날짜 탭은 스냅샷이라 역할이 겹치지 않는다.

# 4. 실행 결과

## 4.1 테스트 케이스 설계

조건 분기가 2개(총 4개 경로)이므로 **모든 경로가 1회 이상 실행되도록** 2회의 실행으로 설계했다.

| 회차 | 입력 키워드 | 기대 경로 | 검증 목적 |
|---|---|---|---|
| **TC-1** | `vitamin c serum` | 분기① **B** → Loop N회 → 분기② **A**와 **B** 모두 발생 | 정상 흐름 + 품질 분기 양쪽 |
| **TC-2** | `zzqqxxvv nonexistent` | 분기① **A** → 관리자 메일 → 종료 | 실패 감지 경로 |

TC-1에서 상위 N개 안에 평점·리뷰수 편차가 존재하므로, 한 번의 실행으로 분기②의 두 경로가 자연스럽게 모두 실행된다.

## 4.2 실행 결과 캡처

> 아래 자리에 실행 후 캡처를 삽입한다. 파일은 `images/` 폴더에 같은 이름으로 저장하면 자동 표시된다.

# 6. 제약 사항 준수

## 6.1 보안

| 항목 | 조치 |
|---|---|
| API Key · 토큰 | relay.app OAuth 연동만 사용, 화면 노출 없음 |
| 계정 이메일 | 캡처에 미노출 |
| Google Spreadsheet ID | 시트명(`bestsellers`, `벤치마킹`, `참고_일반`)만 노출, 문서 ID 미노출 |
| Form Responder link | Trigger 캡처에서 `tugEu76q-**********` 로 마스킹 완료 |

## 6.2 과금

- relay.app **무료 플랜 범위 내**에서 전 기능 구현, 유료 결제 없음
- AI 스텝은 무료 AI credits로 동작
- Google Sheets·Email은 무료 사용
- **AI 크레딧 소진 시 무료 대안**: ① 자체 OpenAI API Key 연결로 전환 ② Step 10을 생략하고 Step 5 결과(6개 필드)만 적재하는 축소 버전 운영

## 6.3 대상 사이트 이용 조건

- 공개된 검색·상세 페이지의 **텍스트만** 조회하며 로그인·결제 영역에는 접근하지 않는다.
- 1회 실행당 요청 수는 검색 2회 + 상세 N회로, 상시 폴링이 아닌 **사용자 요청 시점의 1회성 조회**다.
- 수집 데이터는 사내 시장조사 목적으로만 사용하고 재배포하지 않는다.

# 7. 한계 및 개선 계획

| 항목 | 내용 | 개선 방향 |
|---|---|---|
| Step 5 프롬프트 수치 불일치 | *"상위 **5개** 추출 … **30개** 미만이면 있는 만큼"* — 두 숫자가 충돌하며 스텝명의 "n개"와도 어긋남 | 폼에 `수집 개수`(숫자, 기본 5) 필드 추가 후 프롬프트를 `{1.수집 개수}` 로 파라미터화 |
| 벤치마크 알림 다발 | Step 14가 Loop 안에 있어 조건 충족 상품 수만큼 메일 발송 | Loop 밖으로 이동해 후보 목록을 1통으로 묶어 발송, 또는 순위 3위 이내 조건 추가 |
| 가격이 문자열 | `$24.99` 형태라 시트 집계 불가 | Step 11에 `가격_숫자` 출력 추가 (통화기호·쉼표 제거 후 Parse as number) |
| 탭 이름 충돌·특수문자 | 같은 키워드를 같은 분에 두 번 실행 시 중복, 키워드에 `/`·`[`·`]` 포함 시 생성 실패 | 탭명에 `HH:mm:ss` 포함, Step 2 방식으로 특수문자 치환 |
| 시트명 표기 불일치 | 스텝명은 "벤치마크_후보 탭"인데 실제 Sheet는 `벤치마킹` | 둘 중 하나로 통일 |
| 정렬 파라미터 의존 | `s=exact-aware-popularity-rank` 는 아마존이 변경할 수 있음 | 0건 분기 알림으로 조기 감지되며, 변경 시 Step 2의 Append 값만 수정 |
| 실제 BSR 미수집 | 현재 "순위"는 정렬 결과의 노출 순서 | Step 10 출력에 `BSR`·`BSR 카테고리` 필드를 추가하고 상세 페이지의 *Best Sellers Rank* 항목을 그대로 옮기도록 프롬프트에 명시 |

## 확장 계획 — 완전 무인 정기 모니터링

과제 요건상 Form 제출도 정상적인 Trigger지만, "매주 정기 모니터링"이라는 실제 업무 목적에는 사람이 폼을 여는 행위가 남는다.

동일 워크플로우를 복제해 Trigger를 **Schedule(매주 월요일 09:00)** 로 바꾸고, 키워드는 Google Sheets `키워드_마스터` 탭을 읽어 Loop로 순회한다. 폼 버전은 애드혹 조회용, 스케줄 버전은 정기 모니터링용으로 병행 운영한다.
